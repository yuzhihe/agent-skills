# 粤语词语、短语与短句串联记忆生成器

将零散学习条目转化为有具体情景、连贯情节和准确解释的香港口语文章。每个目标获得有效语境和可查解释；按用户选择呈现粤拼、注释与文章结构。

## 1. 接手项目与质量参考

- 先读适用的项目规则、当前进度和已有索引；有用户认可的成品时，选一篇近期且相关的正式文章阅读。
- 从成品与用户要求确定学习水平、口语风格、文章与 Part 结构、词汇密度、粤拼位置、解释语言及交付方式。保留已确认的选择，不反复询问。
- 参考成品的质量特点，按新词组织新情景，不机械复制人物、剧情或主题；不为统一新格式擅自改写已认可文章。
- 没有项目要求时采用自然繁体香港口语、情境故事和可查的粤拼释义。普通话对照、练习题、音频、网站及额外交接文件不因使用本技能自动加入。
- 项目的每篇容量、专题数量、目录路径和网页样式由项目决定，不将某一项目的数字或格式变成所有任务的固定要求。

## 2. 输入解析与学习项分类

接受可读取的表格、数据库导出、JSON、HTML、Markdown、纯文本及其他结构化或半结构化材料。

1. 检查结构、编码、字段、样例和重复模式，推断词目、词形、粤拼、义项、例句及来源。格式可可靠推断时直接继续；不同解析会显著改变目标范围时才澄清。
2. 保留原始条目、源读音、源释义、收藏来源与词条 ID，不改写源文件或源应用数据库。界面字段、时间、收藏状态不得识别成生词。
3. 分清个人收藏、词典内容和其他词书来源；源记录数不等于目标数，义项数、例句数也不等于独立词条数。
4. 无法解码的材料说明限制，不猜测。少量读音、义项或来源不确定的条目可留待处理，先完成其余确定项并报告数量。

学习项类型：

- `word`：词语或固定词形；
- `phrase`：惯用语、固定搭配或较短表达；
- `sentence`：需要整体记忆的完整句子；
- `example`：词典附带例句，不自动成为独立学习目标。

结合实际表达判断类型，词典的“語句”等标签不必然代表完整句子。同一完整句子不得拆成普通词重复计算；同一词与包含它的较长表达可分别作为目标。

## 3. 去重、义项与续写

### 历史与有效覆盖

- 优先读取 `00_已使用詞條索引.jsonl`，兼容既有简体文件名和字段。索引缺失时，按成品实际标注方式识别目标：加粗加粤拼、提示链接或明确词条引用均可，不仅识别词汇表。
- 从正文、补充对话或情境例句确认实际用法，再与提示、注释或词汇表关联。只出现在解释区、普通正文偶然出现或未经核验的字符串命中，不自动视为目标已覆盖；项目有更具体的已出现判定规则时依其执行。
- 索引与正文有明确冲突时复核相关记录，以可核查内容和用户确认结果为准，不无目的重建全部历史。
- 无可用历史时仅做本批去重，说明历史使用情况未确认。已用词可以自然复现，不重复算新增目标。

### 词条身份与义项

- 有来源 ID 时，用来源加 ID 追踪词条，同时保留原词形、异体与实际正文词形。不同 ID 不仅凭字面相同自动合并；同一来源词条的多个异体不机械重复计数。
- 用 Unicode 兼容规范化、首尾空白、空格及可靠的全半角差异生成比较键；保留原文。完整句子只做可靠格式级去重，不用宽松语义相似度删句，不删掉影响语气或句型的标点。无法确认等价的字形、近义词和相似表达不自动合并。
- 同一词条、同一目标义项已有效覆盖，可排除；字面相同但含义、读音或用法明显不同，保留为待学义项。
- 义项有源 ID 时优先使用；只有序号时同时保留源释义及批次信息，词典更新后不能只凭旧序号判重。
- 分开统计独立词条覆盖、义项覆盖和普通正文出现证据。索引记录数不等于独立词条数；文章覆盖不代表用户已掌握。

### 编号与索引

沿项目已有层级编号：如果是每篇文章包含多个 Part，新文章编号接最大篇号，每篇内部 Part 可从 1 起；如果项目采用全局 Part 编号，接最大 Part。没有历史时从 1 开始，不覆盖或重编号旧文。没有新目标时不生成空篇。

用户要求保存、交付文件或项目已有索引流程时，先生成并验收，再更新实际覆盖记录。失败、待处理或未交付项不得标为已使用。保留现有索引格式；具备相应信息时记录：

```json
{"source":"words.hk","entry_id":79397,"normalized_key":"論盡","original":"論盡","surface_form":"論盡","type":"word","sense_index":1,"source_definition":"手腳或者諗嘢唔靈活引起唔方便、笨手笨腳；唔小心","meaning":"笨手笨腳，做嘢唔夠靈活。","jyutping":["leon6 zeon6"],"article":"02_文章名.md","location":"02 / Part 1","batch":"YYYY-MM-DD","status":"delivered"}
```

没有来源 ID 时不伪造，使用可追踪的原条目、比较键和实际义项。已验收的本地文章也参与去重；交付、用户认可、网站构建和线上发布分别记录，不因尚未上线再次生成。

## 4. 分篇、密度与情节

- 按语义场景与认知复杂度组织。用户要求一篇完整主题文章时，先确定贯穿事件，再以不同侧面分成相互关联的 Part。
- 采用项目已确认的容量和成品密度。没有约定时，每个可独立阅读的 Part 或单元可先按约 15–30 个目标估计；短句、复杂俗语较多时适当减少。这些是起点，随任务规模、语义关联和阅读负担调整，不强制套固定数量或层级。
- 大批任务结合用户希望的总篇数和每篇容量规划，避免拆得过碎。核对实际覆盖密度，不能仅靠拉长正文达成数量。
- 先形成具体人物、冲突或事件及推进过程，再安置目标。通用词分配到合适位置，跨度太大时换微场景或分篇，不突然转题。
- 优先主故事和关联对白；少数不适合主线的项可放简短补充对话或情境例句。不要把大部分目标移到后备区，也不为凑数写清单式台词。
- 修改或扩充后检查时间顺序、人物到场、物件位置、动作、承诺和结果是否前后一致，特别留意新增段落造成的冲突。

## 5. 粤拼、语境释义与呈现

每个有效目标必须有准确、可查的解释；可放在提示、词汇表或关联注释中，不强制重复制作全量词汇表。

### 按项目选择呈现

- **行内注音**：`**詞語 (jyutping)**`，适合明确需要直接看读音的文档。
- **按需提示**：`[詞語](# "jyutping｜粵語解釋")`，适合正文不直接露出粤拼的 Markdown 或网页阅读；采用既有渲染器支持的转义规则，检查引号、括号及长句不会破坏标记。
- **完整句子**：优先作为对白、讯息或情节关键句整体出现。完整粤拼可放提示或关联解释区，避免长行内注音打断阅读。疑似有误且用户要求原样记忆的句子，不擅自改写。

提示释义解释本处实际义项，不直接取词典第一项。必要时说明讽刺、客气、责怪、粗俗或正式语域，并区分源词典内容与补写的解释和例句。

读音与实际词形、义项对应。优先用来源已有粤拼；多个读音保留来源关系，不把别的异体读音混配过来。缺失或特殊非标准标记不猜补成标准粤拼，记录待核实情况。

文后注释重点解释偏僻、重要、近义或容易误用的表达。解释语言依用户选择；用户要求粤语解释时，不改成普通话翻译。每项已有可查解释时不重复附全量词表。

按需提示标记只提供数据，即时显示由渲染层实现。若任务包含网页制作，采用自定义即时提示，悬停时同时显示粤拼与释义，不依赖有默认等待延迟的浏览器 `title`。检查点击、键盘、长提示和手机边界；只有实际验证后才能称为网页体验通过验收。仅生成文章时不自动建站或加阅读功能。

## 6. 自然香港口语与内容边界

- 叙述和对白都采用自然、现代的香港口语，依家庭、朋友、职场、服务行业等人物关系选择语域。
- 使用粤语语序、体貌、连接和语气，不以机械堆入 `喺`、`咗`、`嘅` 代替真实句法。书面腔或普通话语序要整句重写，不只换字。
- 正文与标题默认繁体；正式术语可以保留，周围句法仍要自然。源词形、异体和来源信息保留，不因统一显示字形丢失追踪关系。
- 不刻意加入老派、小众或粗俗黑话，除非其本身是目标。
- 负面、冲突或敏感词在必要、真实且克制的语境呈现，保留准确词义和后果，不美化伤害、不拿受害者作笑料。按情景选择生活、新闻、影视等语境，不机械套法治讲座或剧组排练。

## 7. 可选多义词专题

用户要求或项目已有安排时，筛出不同意思差异明显、容易混淆的词；轻微语义差别不机械拆篇。

用不同情景呈现各义项，解释如何由上下文、搭配或语气分辨。专题数量与安排时机依项目决定，不规定每个多义词都写一篇。复用已覆盖词时记录新增义项，不重复增加独立词条覆盖数；只覆盖部分义项的词，其他义项仍保留待学。

## 8. 验收与交付

完成一次完整验收；发现问题时针对修复并复验，不无目的反复重写。

- **范围与数量**：源记录、有效学习项、本批重复、历史重复、待处理及本次目标能对上；词条数与义项数分别计算。
- **有效覆盖**：每个目标进入正文、补充对话或情境例句，有匹配解释；短语、句子保持整体，标注与索引所在篇目、Part、实际词形和义项一致。
- **读音与格式**：来源粤拼对应实际词形；提示或行内标记格式正确。存在网页产出时检查源文章、词卡与索引一致。
- **语义与口语**：逐段回读，确认语境义项、人物语域、香港口语句法和释义准确，避免硬塞词、书面腔或突兀转题。
- **情节与连续性**：人物、时间、动作、物件和前后因果一致，尤其复核扩充或修订部分。
- **历史与状态**：编号沿既有规则，旧文未被覆盖；索引只记录成功交付目标，不把构建或打包记为发布。

自动检查负责数量、标记、位置与数据一致性；语义、口语和情节须通读复核，不能用字符串命中代替。按既有工具做必要检查，不为每批重新搭建工具体系。

采用项目已认可的结构；无既有格式时，使用标题、关联单元或 Part、情境正文及必要解释区即可。输出实际请求的文章和索引，简要报告，例如：

```text
本次目标：96 项｜生成：1 篇 3 Parts｜有效覆盖：96/96｜待处理：2 项
```
