# 案例模板

每个案例先建 `meta.json`，它是索引和浏览页的唯一维护入口。下面的标签和取值以 `scripts/build_library.py` 中的 `TASKS`、`DENSITY`、`ASSET`、`TONE`、`LANG`、`PATTERNS` 为准；出现无法用现有标签表达的明确需求时再扩展，不硬套错误标签。`order` 是浏览顺序，须唯一，不是推荐排名。`summary` 用一句话讲清可借鉴的组织方式，`usage` 简述适合条件。

`patterns` 是可选的设计模式标签数组，只标注案例确有证据的模式；没有对应模式可省略或留空。`caveat` 是可选的单行使用边界，优先写会影响选择的限制，例如“仅组件状态；窄屏矩阵有裁切”或“结账未提交订单”。新收录案例应填写，已有旧格式仍可读取；详细未验证项保留在正文，不重复塞进索引。

```json
{
  "order": 21,
  "id": "example-site",
  "name": "Example Site",
  "source": "https://example.com/",
  "studied": "2026-10-05",
  "tasks": ["discovery"],
  "density": "medium",
  "assets_needed": ["content-previews"],
  "tone": ["neutral"],
  "lang": "en",
  "summary": "搜索入口与精选内容并置，帮助用户在浏览和查找之间切换。",
  "usage": "适合有足够资源和可用预览的发现页；资源很少时不需要复杂筛选。"
}
```

`analysis.md` 复制以下结构并填入真实结果。来源与日期如在正文重复，应与 `meta.json` 一致。未知项明确写“未验证”；无需为每个格子勉强填数。

```markdown
# 案例名称 · 设计特点

- 标识：稳定的小写英文名
- 来源：完整 URL
- 研究日期：YYYY-MM-DD
- 页面范围：主页首屏 / 内容区 / 指定子页面
- 证据范围：截图、计算样式、操作；分别说明
- 视口与状态：宽×高、滚动位置、菜单等状态
- 适合：任务、内容密度和受众
- 不适合：冲突场景
- 素材依赖：图片、插画、产品截图、字体

## 视觉证据
相对截图链接 + 每张图的重点及限制。

## 可观察的设计关系
给出三至五个具体关系；事实与分析判断分开。

## 实测参数
元素/定位说明 | 属性 | 实测值 | 对应证据文件
注明适用视口；不以建议值冒充实测值。

## 响应式与交互
实际尝试的操作和结果。未测部分明确列出。

## 迁移方法（设计建议）
如何把这些关系转为新内容和组件；字体替代；缺少素材时怎么办。

## 避免照搬与已知限制
会破坏效果的用法、未验证项、动态页面的局限。
```
